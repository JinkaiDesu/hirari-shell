# Hirari / Skunkworks integration

Hirari remains independently runnable. No Unity connection is attempted until a
`unity` operation needs it. This integration does not invoke another runtime or
interpreter. Domain tooling remains ordinary Seed programs and external tools.

## Build and tests

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

MSVC uses `/MT` in Release and `/MTd` in Debug. Tests compile their own native
process helper and use temporary neutral worlds, including paths with spaces
and Unicode. They require no host-installed Python, Git, Bash, or Unity.
The protocol test peer validates messages and failure behavior; actual player
and bundled-tool acceptance belongs to Skunkworks' package tests.

`hirari/wire_generated.hpp` is generated by Skunkworks from its canonical
`Dev/Protocol/schema.json`. It is checked into this source integration; do not
hand-edit or create another enum definition. Current limits are 1 MiB per frame
and 4,096 values. Framing is little-endian int32 body length, then message kind
byte, int64 request ID, int32 value count, and tagged values. Strings use int32
UTF-8 byte length, not BinaryWriter's built-in string encoding. Batch entries are
Bytes containing a packed message body without the frame length prefix.

## Scripts

```powershell
hirari --eval ':foo'
hirari --file 'path with spaces/start.seed'
```

No arguments starts the interactive shell. `--eval` evaluates one Seed source
form. `--file` evaluates UTF-8 expressions in order, one per completed line;
quoted or grouped expressions can span lines, and UTF-8 BOMs are accepted.
Script files keep the caller's working directory. World opening sets the world
root explicitly. Script errors include file/line diagnostics and return nonzero.
External program failures stop script execution. A script can launch a foreground
interactive tool when Hirari has a console; it resumes after that tool exits.
Redirected/non-console calls use captured or streaming process execution.

## Unity primitives and identity

Set `SKUNK_UNITY_PIPE` in the child environment to the desired local pipe name,
for example `skunkworks.unity.<player PID>`. When absent, Hirari uses
`skunkworks.unity`. An endpoint is a name, not a `\\.\pipe\...` path.
`unity connect` is optional: the first operation connects automatically.

The persistent client sends Hello with String(`skunkworks.wire/1`) and requires
Ready with the same version string and a session GUID. The player uses N32
(32 hexadecimal characters); the client also accepts D36 GUIDs and preserves
the exact session string for equality checks. It checks response IDs,
frame/value bounds, partial reads, faults, and disconnects. A connection fault
or timeout closes the transport. The next operation reconnects and handshakes;
it never automatically replays the failed operation. A broker Fault keeps a
healthy connection available. Requests have a five-second timeout and support
host interruption. A timed-out mutation may already have executed.

Seed `NAME := FORM` and `FORM = NAME` retain the same lazy program form. In particular,
`go := unity new t "GenericProof"` runs New again whenever `go` is demanded.
Use the **explicit host capture** operation for a retained capability value:

```text
unity bind :t (unity type "UnityEngine.GameObject")
unity bind :go (unity new t "GenericProof")
unity get go "name"
unity set go "name" "RenamedProof"
unity get go "name"
unity call go "SetActive" :false
unity bind :transformType (unity type "UnityEngine.Transform")
unity bind :transform (unity component go transformType)
unity find "RenamedProof"
unity release transform
unity release go
```

`unity bind :destination expression` requires a Name of a symbol, reduces the
expression once, binds that evaluated identity/value, and returns it. Native
`=` is not replaced. Object/type references use immutable Name identities with
typed payloads owned by host Program contexts. They are not ordinary strings or
user-entered numeric handles. Diagnostic labels are display information.
Released references and references from another endpoint/session are rejected
before transmission. Reconnecting to the same server session permits retained
unreleased references; restarting Unity invalidates them.

Supported primitives are `find`, `type`, `component`, `get`, `set`, `call`,
`new`, `release`, and `batch`. `unity status` reports local transport state;
`unity disconnect` closes it. Find resolves registered roots or named objects.
Component gets an existing component; AddComponent is an ordinary CLR call.
Unity executes these operations through its own main-thread queue.

Quoted literals stay String values. `:true` and `:false` encode Boolean; `()`
encodes Null. Unbound numeric tokens encode Int32/Int64 or Double. Arbitrary
Names are rejected as text. Returned numbers retain their wire kind and exact
value in opaque host payloads. Skunkworks retains returned CLR arrays, including
`byte[]` at every size, as object references rather than copying their contents
into a response. Explicit constructors are:

```text
unity bind :count (unity i32 "12")
unity bind :large (unity i64 "9223372036854775807")
unity bind :weight (unity f32 "1.25")
unity bind :precise (unity f64 "1.25")
unity bind :payload (unity bytes "00ff01")
unity string "literal text"
```

Integer helpers validate range; floats reject non-finite input. Bytes use
even-length hexadecimal text. `unity string` accepts a quoted literal only.

`unity bytes` is an explicit bounded input payload. A returned array is instead
an opaque CLR reference: capture it once with `unity bind`, then reuse it directly
in subsequent CLR calls, including within a batch. For example:

```text
unity bind :fileType (unity type "System.IO.File")
unity bind :payload (unity call fileType "ReadAllBytes" "artifact.bin")
unity get payload "Length"
unity call fileType "WriteAllBytes" "copy.bin" payload
unity release payload
```

The bytes stay inside Unity/Mono. Release drops that broker handle, not any other
owner's reference or the underlying resource. Ordinary `:=` / inverse `=` retains
the program form and can repeat the read; it does not capture the array once.
File I/O remains synchronous on Unity's main thread. This changes no Seed syntax
or wire tags, and does not add automatic disposal, client leases or bulk export.

## Explicit CLR signatures and generic methods

```text
unity bind :stringType (unity type "System.String")
unity bind :boolType (unity type "System.Boolean")
unity bind :go (unity new-exact t :(stringType) "GenericProof")
unity call-exact go "SetActive" :(boolType) :true
```

`new-exact TYPE :(SIGNATURE_TYPES) ARGUMENTS...` supplies the exact constructor
signature. `call-exact TARGET "METHOD" :(SIGNATURE_TYPES) ARGUMENTS...` does the
same for a method. `:()` is an exact empty signature. Signature count must match
argument count. Ordinary New/Call use inferred overload resolution.

Generic methods use `call-generic TARGET "METHOD" :(GENERIC_TYPES) ARGUMENTS...`
or `call-generic-exact TARGET "METHOD" :(GENERIC_TYPES) :(SIGNATURE_TYPES)
ARGUMENTS...`. Lists are reified Seed products, not a second language.

Managed assembly loading uses the existing reflection primitive:

```text
unity bind :assemblyType (unity type "System.Reflection.Assembly")
unity bind :assembly (unity call assemblyType "LoadFrom" "absolute/path/Extension.dll")
```

## Batches

```text
unity bind :results (unity batch :(
    (type "UnityEngine.GameObject")
    (new (unity batch-ref 0) "GenericProof")
    (get (unity batch-ref 1) "name")
))
unity at results 2
unity bind :go (unity at results 1)
```

Batch-ref indices refer to the primary result of an earlier operation.
`unity at` selects a zero-based result without converting foreign identities.
Batches run sequentially and are not transactional. On a fault, earlier
operations may already have executed.

## Generic world contract

A world root contains this minimal descriptor and an ordinary Seed entry file:

```toml
[world]
name = "Example world"
version = 1

[entry]
program = "start.seed"
```

```text
world open "path/to/Example world"
world status
```

The v1 descriptor accepts only `[world]` name/version and `[entry]` program.
It supports comments, whitespace, single-quoted literal strings, basic
single-line quoted strings and TOML escapes. Duplicate/unknown fields or
tables, missing fields, empty names and unsupported versions fail explicitly.
The entry must be an existing file within the canonical world root, including
after resolving symlinks/junctions; absolute and escaping paths are rejected.

Opening validates first, selects the world, sets the process working directory
to its root, exposes `SKUNK_WORLD` to native child processes, and executes the
entry. Failure restores the previous world selection, actual working
directory, and prior environment value (including absence). Rollback covers
host selection/environment; it does not undo side effects the entry already
performed, such as files, Seed bindings, or Unity allocations. `world status`
reports `stopped` before a successful open. No world-specific content or rules
are implemented here.

## Shell tool programs

Unity is a target of the shell. Domain commands belong in `.seed` programs and
external tools, not in Hirari builtins or player-specific loaders.

```text
run "tools/build-content.seed" "input with spaces.png"
source "tools/vocabulary.seed"
exec "C:/Program Files/Some Tool/tool.exe" "literal argument"
```

An unbound command resolves to a builtin first, then a native executable using
the existing PATH policy, then a `.seed` file. Seed lookup searches the calling
script's directory, the current directory, `SKUNK_SYSTEM/Commands`, `HIRARI_PATH`, and PATH, in that
order. `HIRARI_PATH` uses semicolon-separated directories on Windows. An
explicit `.seed` filename or `run` selects a Seed program without competing
with an executable of the same stem. Nested `run`/`source` includes resolve
relative to the calling file before the working directory. Source files are
read on each invocation, so editing a command does not require shell restart.

`arg 0` returns the first supplied value. `args` returns a captured product of
all argument values. Names, literals, Unit and retained Unity references stay
distinct; they are not reparsed command strings. The CLI also accepts
`hirari --file tool.seed argument...`, projecting native argv into literals.

Discovered commands and `run` restore caller binding heads/revisions, working
directory and world selection after success or failure. `source` exports its
binding/context changes into the caller. Both restore the previous argument
frame. An executed command returns its last result in the same evaluator;
a Unity object returned by it remains usable after the call ends. File writes,
external processes, Unity objects and mutations are not rolled back. This is
a synchronous call scope, not persistent cells, closure capture or a sandbox.
New cells still occupy the runtime arena, and reflected handles still require
explicit lifecycle management.

Nesting is bounded at 64 files. Failures include file and source line, preserve
the failed tool's stdout/stderr and stop the calling script. `exec` uses the
ordinary native process machinery synchronously with captured streams; it
does not pass a command string to PowerShell/Bash or start an interactive
foreground terminal. Ordinary unquoted executable commands retain their
existing foreground behavior, including when called from a script.

Content can be generated, built and loaded while the player stays running.
AssetBundle compilation requires an external compatible Unity Editor; loading
a built bundle uses the existing player AssetBundle API. Neither workflow
requires a new Seed operator or a content-specific runtime class.

## Callable vocabulary and help

```text
recent := git "log"
recent "--oneline"
? recent
recent help
apply :(exec "program.exe" "fixed argument") (args)
```

Callable heads expand retained structure and append arguments without reparsing
text. Alias cycles/depth are bounded. Names, text and Unit stay distinct in
same-evaluator script calls. `apply` invokes a reified program with a reified
argument product; it is also useful for forwarding a command file's `args`.

In Hirari, `? SUBJECT`, `SUBJECT help` and `help SUBJECT` inspect the subject
without invoking it. Builtins expose usage, aliases expose definitions and
revisions, files expose their origin and leading comments, and retained CLR
objects expose public member metadata without executing getters. Native command
documentation is invoked explicitly with `exec "path" "--help"` or a quoted
`"help"` argument. `demand SUBJECT` preserves explicit Seed evaluation. Pure
Seed retains its demand primitive; Hirari supplies reflective help above it.
`unity help TARGET ["MEMBER" OFFSET COUNT]` paginates CLR metadata.

## Persistence and lifetimes

Interactive top-level definitions save automatically to
`%LOCALAPPDATA%/Hirari/vocabulary`. `HIRARI_STATE` selects a store; `-` disables
it. Noninteractive scripts and local calls remain transient unless explicitly
saved. An established definition persists even if its initial command fails;
restoring/reloading does not add a second automatic revision. `source` can export
definitions into the interactive caller.

```text
vocab save :recent "Show repository history"
vocab history :recent
vocab restore :recent 1
vocab forget :recent
vocab use "world-local vocabulary"
```

The snapshot stores tagged forms, annotations and revisions, never startup code
or runtime pointers. Loading does not execute definitions. Commits flush and
atomically replace the previous snapshot under an exclusive write lock; damage,
read-only storage, or size/history limits leave the shell usable and the previous
file intact. Concurrent writes merge unrelated definitions; existing sessions
must reload with `vocab use` to see another session's changes. Same-name updates
use commit order. Limits are 16 MiB and 10,000 revisions; compaction/export is not
implemented. A saved program can reconstruct/find a live object, but an opaque
CLR identity itself cannot be saved. This is definition persistence, not closure,
process, database, or Unity resource persistence.

Broker references belong to one pipe connection. Disconnect, shell death, or
explicit `unity disconnect` releases that connection's handles on Unity's thread.
Reconnecting receives a new session; reacquire objects with `find`/`type`.
Releasing handles does not destroy Unity objects or dispose CLR resources.
The broker has a combined 65,536-handle limit and an explicit generic limit
setter. Arrays remain references at every size; the control frame remains bounded.

`unity wait REQUEST ["completionMember" TIMEOUT_MS]` polls on the shell side
without blocking Unity frames. The default is `isDone`, 10 seconds; timeout is
bounded at 300 seconds. Ctrl+C or timeout cancels the wait; the underlying Unity
operation can continue. It is not an operation rollback.

## Live script/native streams

Pipelines with a native stage can run `.seed` stages as independent Hirari
`--stream-file` processes with live stdin/stdout. Their native child output is
forwarded as it arrives. A failed upstream stage makes the pipeline fail even
when the final stage succeeds. Process cancellation uses the existing job owner.
Pure Seed composition remains structured in the same evaluator.

This boundary carries bytes and ordinary OS arguments. It does not export the
caller's bindings, closures or CLR handles. Opaque references passed as native
argv fail explicitly; use a structured Seed call for them. Captured native output
has a 16 MiB budget; use live streams or artifact files for larger outputs.

Known limits: synchronous reflected file reads still execute on Unity's thread;
handles avoid bulk wire transfer but not I/O, allocations or GPU uploads. The
arena retains evaluated forms during the session. No database-backed namespace,
automatic object destruction, or representation materialization is introduced.
