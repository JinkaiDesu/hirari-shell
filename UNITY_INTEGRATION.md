# Hirari / Skunkworks integration

Hirari remains independently runnable. No Unity connection is attempted until a
`unity` operation needs it. This integration does not invoke another runtime or
interpreter. The Seed evaluator sources are unchanged.

## Build and tests

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

MSVC uses `/MT` in Release and `/MTd` in Debug. Tests compile their own native
process helper and use temporary neutral worlds, including paths with spaces
and Unicode. They require no host-installed Python, Git, Bash, or Unity.
The protocol test peer validates messages and failure behavior; actual player
and bundled-tool acceptance belongs to Skunkworks' package tests.

`hirari/wire_generated.hpp` is generated by Skunkworks from its canonical
`Dev/Protocol/schema.json`. It is checked into this source integration; do not
hand-edit or create another enum definition. Current limits are 1 MiB per frame
and 4,096 values. Framing is little-endian int32 body length, then message kind
byte, int64 request ID, int32 value count, and tagged values. Strings use int32
UTF-8 byte length, not BinaryWriter's built-in string encoding. Batch entries are
Bytes containing a packed message body without the frame length prefix.

## Scripts

```powershell
hirari --eval ':foo'
hirari --file 'path with spaces/start.seed'
```

No arguments starts the interactive shell. `--eval` evaluates one Seed source
form. `--file` evaluates UTF-8 expressions in order, one per completed line;
quoted or grouped expressions can span lines, and UTF-8 BOMs are accepted.
Script files keep the caller's working directory. World opening sets the world
root explicitly. Script errors include file/line diagnostics and return nonzero.
External program failures stop script execution. Foreground interactive tools
belong in the interactive shell. This adds no new Seed syntax or comment form.

## Unity primitives and identity

Set `SKUNK_UNITY_PIPE` in the child environment to the desired local pipe name,
for example `skunkworks.unity.<player PID>`. When absent, Hirari uses
`skunkworks.unity`. An endpoint is a name, not a `\\.\pipe\...` path.
`unity connect` is optional: the first operation connects automatically.

The persistent client sends Hello with String(`skunkworks.wire/1`) and requires
Ready with the same version string and a session GUID. The player uses N32
(32 hexadecimal characters); the client also accepts D36 GUIDs and preserves
the exact session string for equality checks. It checks response IDs,
frame/value bounds, partial reads, faults, and disconnects. A connection fault
or timeout closes the transport. The next operation reconnects and handshakes;
it never automatically replays the failed operation. A broker Fault keeps a
healthy connection available. Requests have a five-second timeout and support
host interruption. A timed-out mutation may already have executed.

Seed `=` retains its existing lazy RHS program form. In particular,
`go = unity new t "GenericProof"` runs New again whenever `go` is demanded.
Use the **explicit host capture** operation for a retained capability value:

```text
unity bind :t (unity type "UnityEngine.GameObject")
unity bind :go (unity new t "GenericProof")
unity get go "name"
unity set go "name" "RenamedProof"
unity get go "name"
unity call go "SetActive" :false
unity bind :transformType (unity type "UnityEngine.Transform")
unity bind :transform (unity component go transformType)
unity find "RenamedProof"
unity release transform
unity release go
```

`unity bind :destination expression` requires a Name of a symbol, reduces the
expression once, binds that evaluated identity/value, and returns it. Native
`=` is not replaced. Object/type references use immutable Name identities with
typed payloads owned by host Program contexts. They are not ordinary strings or
user-entered numeric handles. Diagnostic labels are display information.
Released references and references from another endpoint/session are rejected
before transmission. Reconnecting to the same server session permits retained
unreleased references; restarting Unity invalidates them.

Supported primitives are `find`, `type`, `component`, `get`, `set`, `call`,
`new`, `release`, and `batch`. `unity status` reports local transport state;
`unity disconnect` closes it. Find resolves registered roots or named objects.
Component gets an existing component; AddComponent is an ordinary CLR call.
Unity executes these operations through its own main-thread queue.

Quoted literals stay String values. `:true` and `:false` encode Boolean; `()`
encodes Null. Unbound numeric tokens encode Int32/Int64 or Double. Arbitrary
Names are rejected as text. Returned numbers and bytes retain their wire kind
and exact value in opaque host payloads. Explicit constructors are:

```text
unity bind :count (unity i32 "12")
unity bind :large (unity i64 "9223372036854775807")
unity bind :weight (unity f32 "1.25")
unity bind :precise (unity f64 "1.25")
unity bind :payload (unity bytes "00ff01")
unity string "literal text"
```

Integer helpers validate range; floats reject non-finite input. Bytes use
even-length hexadecimal text. `unity string` accepts a quoted literal only.

## Explicit CLR signatures and generic methods

```text
unity bind :stringType (unity type "System.String")
unity bind :boolType (unity type "System.Boolean")
unity bind :go (unity new-exact t :(stringType) "GenericProof")
unity call-exact go "SetActive" :(boolType) :true
```

`new-exact TYPE :(SIGNATURE_TYPES) ARGUMENTS...` supplies the exact constructor
signature. `call-exact TARGET "METHOD" :(SIGNATURE_TYPES) ARGUMENTS...` does the
same for a method. `:()` is an exact empty signature. Signature count must match
argument count. Ordinary New/Call use inferred overload resolution.

Generic methods use `call-generic TARGET "METHOD" :(GENERIC_TYPES) ARGUMENTS...`
or `call-generic-exact TARGET "METHOD" :(GENERIC_TYPES) :(SIGNATURE_TYPES)
ARGUMENTS...`. Lists are reified Seed products, not a second language.

Managed assembly loading uses the existing reflection primitive:

```text
unity bind :assemblyType (unity type "System.Reflection.Assembly")
unity bind :assembly (unity call assemblyType "LoadFrom" "absolute/path/Extension.dll")
```

## Batches

```text
unity bind :results (unity batch :(
    (type "UnityEngine.GameObject")
    (new (unity batch-ref 0) "GenericProof")
    (get (unity batch-ref 1) "name")
))
unity at results 2
unity bind :go (unity at results 1)
```

Batch-ref indices refer to the primary result of an earlier operation.
`unity at` selects a zero-based result without converting foreign identities.
Batches run sequentially and are not transactional. On a fault, earlier
operations may already have executed.

## Generic world contract

A world root contains this minimal descriptor and an ordinary Seed entry file:

```toml
[world]
name = "Example world"
version = 1

[entry]
program = "start.seed"
```

```text
world open "path/to/Example world"
world status
```

The v1 descriptor accepts only `[world]` name/version and `[entry]` program.
It supports comments, whitespace, single-quoted literal strings, basic
single-line quoted strings and TOML escapes. Duplicate/unknown fields or
tables, missing fields, empty names and unsupported versions fail explicitly.
The entry must be an existing file within the canonical world root, including
after resolving symlinks/junctions; absolute and escaping paths are rejected.

Opening validates first, selects the world, sets the process working directory
to its root, exposes `SKUNK_WORLD` to native child processes, and executes the
entry. Failure restores the previous world selection, actual working
directory, and prior environment value (including absence). Rollback covers
host selection/environment; it does not undo side effects the entry already
performed, such as files, Seed bindings, or Unity allocations. `world status`
reports `stopped` before a successful open. No world-specific content or rules
are implemented here.
